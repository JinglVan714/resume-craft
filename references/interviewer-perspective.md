# 面试官视角审查指南

> 本文件是简历诊断和面试官盲审的核心指导。包含面试官的真实行为模式、审查清单和分级标准。

---

## 一、面试官筛选简历的真实行为

> 以下来自校招面试官的真实分享（已脱敏）。

### 30秒规则

面试官平均花 30 秒扫一份简历。在这 30 秒内，面试官的视线轨迹：

1. **第一眼**：姓名、学校、目标岗位（2秒）
2. **第二眼**：最近的实习/项目经历标题（5秒）
3. **第三眼**：项目描述中的关键词和技术栈（10秒）
4. **第四眼**：量化成果（5秒）
5. **决定**：继续看 or 跳过（8秒）

如果 30 秒内抓不住重点，简历很可能被跳过。

### 面试官的搜索行为

> "筛简历时不仅看实习和学历，还会搜索一些个人特色的关键词。"

- 有的面试官会搜"游戏经历"
- 有的面试官会搜"开源贡献"
- 有的面试官会搜"竞赛成绩"
- 个人特色关键词有机会被识别到

### 面试官讨厌什么

- 信息堆砌，没有重点
- 描述空洞，只写"负责了XX"
- 技术栈列了 20+ 项但没有项目佐证
- 一份简历走天下，没有针对岗位调整
- 夸大描述，面试深挖时暴露

## 二、审查清单

### 格式审查

- [ ] 排版是否整洁（统一字号、间距、对齐）
- [ ] 信息层级是否清晰（标题 > 正文 > 注释）
- [ ] 关键信息是否突出（加粗、分段）
- [ ] 中英混排是否规范（空格、标点）
- [ ] Markdown 格式是否正确
- [ ] 总长度是否合适（1500-2500字）

### 内容审查

- [ ] 是否有编造信息（与真源不符）
- [ ] 是否有夸大描述（"参与"写成"主导"）
- [ ] 信息密度是否合适（不过于稀疏或堆砌）
- [ ] 是否有无关信息（与目标岗位无关的内容）
- [ ] 时间线是否合理（无矛盾、无重叠）
- [ ] 教育背景是否完整

### 表达审查

- [ ] 是否使用 STAR 结构描述项目
- [ ] 是否有量化成果（数字、百分比、规模）
- [ ] 技术描述是否准确（不泛化、不过度细节）
- [ ] 是否有用户价值描述（解决了什么问题）
- [ ] 是否有技术选型说明（为什么选这个技术）
- [ ] 技能清单与项目经历是否匹配

## 三、审查报告格式

### 输出结构

```
## 简历审查报告

### 整体评分：[X/10]

### 30秒速览
面试官第一眼看到：[姓名、学校、目标岗位]
第二眼看到：[最近的项目/实习]
印象：[一句话评价]

### 亮点
- [亮点1]
- [亮点2]

### 问题清单

**[必须修复]**
1. [问题描述] → [具体修改建议]

**[建议修改]**
1. [问题描述] → [具体修改建议]

**[仅供参考]**
1. [问题描述] → [具体修改建议]

### 总结
[一段话的整体评价和改进方向]
```

### 分级标准

| 级别 | 含义 | 典型场景 |
|------|------|---------|
| [必须修复] | 严重影响简历质量 | 编造信息、严重夸大、关键信息缺失、格式严重问题 |
| [建议修改] | 影响简历效果 | 表达不清、缺少量化、结构不合理、信息堆砌 |
| [仅供参考] | 锦上添花 | 排版细节、措辞优化、风格建议 |

## 四、常见问题模板

### 描述空洞

```
[建议修改] 项目描述过于空泛："负责后端开发"
→ 建议用 STAR 结构重写：
  S：面对什么问题？
  T：你负责什么？
  A：具体做了什么？
  R：效果怎么样？
```

### 缺少量化

```
[建议修改] 项目成果缺少量化数据："提升了系统性能"
→ 建议补充具体数据：
  - 响应时间从 Xms 降至 Yms
  - QPS 从 X 提升至 Y
  - 覆盖 X 万用户
```

### 夸大描述

```
[必须修复] "主导了公司核心系统重构"，但真源显示为"参与"
→ 建议修改为"参与了核心系统重构，负责XX模块的设计与实现"
```

### 信息堆砌

```
[建议修改] 技术栈列了 20+ 项，面试官无法快速抓住重点
→ 建议分层：
  精通(3-5项)：日常主力技术
  熟练(3-5项)：用过多个项目
  了解(2-3项)：学过或用过一两次
```

### 缺少个人亮点

```
[建议修改] 简历中没有个人特色内容
→ 建议补充（如有）：
  - GitHub 开源贡献
  - 技术博客
  - 竞赛成绩
  - 独立项目
```

## 五、审查原则

1. **先肯定亮点** — 不要只指出问题
2. **具体可执行** — 每个问题都给修改建议
3. **分级标注** — 按严重程度排序
4. **站在面试官角度** — 不是"写得好不好"，而是"面试官能不能快速理解"
5. **正直底线** — 不帮用户编造或夸大
6. **参考方向视角** — 结合 `references/job-database.md` 中对应方向的考察重点
